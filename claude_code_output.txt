def make_pipe(C=1.0, cw=None, feats=None):
    feats = feats or FEATURES
    cats = [c for c in CATEGORICAL if c in feats]
    nums = [c for c in NUMERIC if c in feats]
    raws = [c for c in PASS if c in feats]
    tr = []
    if cats:
        tr.append(("cat", OneHotEncoder(drop=[REF[c] for c in cats],
                                        handle_unknown="ignore", sparse_output=False), cats))
    if nums:
        tr.append(("num", StandardScaler(), nums))
    if raws:
        tr.append(("raw", "passthrough", raws))
    pre = ColumnTransformer(tr, remainder="drop", verbose_feature_names_out=False)
    return Pipeline([("pre", pre),
                     ("clf", LogisticRegression(C=C, solver="lbfgs", max_iter=2000,
                                                class_weight=cw, random_state=RANDOM_STATE))])


def topk(y, p, k):
    kn = int(round(len(y) * k))
    sel = np.argsort(-p, kind="stable")[:kn]
    hits = int(y[sel].sum()); prev = y.mean()
    prec = hits / kn if kn else np.nan
    return prec, hits / y.sum() if y.sum() else np.nan, (prec / prev if prev else np.nan), kn, hits


def ece(y, p, bins=10):
    q = pd.qcut(pd.Series(p), bins, duplicates="drop", labels=False)
    t = (pd.DataFrame({"b": q, "p": p, "y": y}).groupby("b", observed=True)
         .agg(n=("y", "size"), mp=("p", "mean"), obs=("y", "mean")))
    return float((t["n"] / t["n"].sum() * (t["mp"] - t["obs"]).abs()).sum())


def cal_slope_int(y, p):
    e = 1e-15
    lp = np.log(np.clip(p, e, 1 - e) / np.clip(1 - p, e, 1 - e))
    m = LogisticRegression(C=np.inf, solver="lbfgs", max_iter=2000).fit(lp.reshape(-1, 1), y)
    return float(m.intercept_[0]), float(m.coef_[0][0])

# Baseline V1 — Methodology and Robustness Audit

**Scope:** read-only audit of Purchase Probability Baseline V1.
**Method:** OOF predictions regenerated deterministically (seed 42, identical code path) because
per-fold lift and calibration diagnostics were not persisted. **TEST was split off and discarded
without ever being scored** — no third opening occurred. No baseline artefact, SQL file, spec or
database object was modified. No model was trained beyond regenerating the four existing fold models.

**Reproduction check — exact:** pooled OOF n = 8,445, positives = 100, A_C1.0 PR-AUC = **0.01943**,
ROC-AUC = **0.60934**. Matches the baseline report to five decimals, so every finding below applies
to the same fitted models the report describes.

---

## 1. Test contamination audit

I audited the chronology from the code and run logs rather than accepting the report's conclusion.

### Chronology established

| Step | Event | TEST scored? |
|---|---|---|
| 1 | Script written with `OneHotEncoder(drop="first")` | — |
| 2 | `--stage oof` run; selection logic found to contradict spec §4.2; selection code fixed | No |
| 3 | Full run 1 → **TEST PR-AUC 0.03034** | **Yes (1st)** |
| 4 | Reading the §12 coefficient table, feature names revealed the true references were `founder_c_level` / `corporate` / `en` — alphabetical, not the most-frequent levels spec §2 mandates | — |
| 5 | Encoder corrected to `drop=[most-frequent per column]` | — |
| 6 | Full run 2 → **TEST PR-AUC 0.03706** | **Yes (2nd)** |

### A. Was any TEST result used to select features, hyperparameters, class weighting, calibration, threshold, or model variant?

**No, on every count — verified against the code, not the narrative.**

| Decision | Fixed by | When |
|---|---|---|
| Feature set (7) | spec §1, hard-asserted in `guard_matrix()` | before any run |
| `C ∈ {0.1, 1.0}` | spec §5 | before any run |
| Class weighting | spec §4.2 rule, computed from OOF margin vs OOF fold spread | before TEST, both runs |
| Calibration method (Platt) | spec §7 | before any run |
| `π_target = 0.797%` | fold 4 validation block, computed from TRAIN | before TEST |
| Threshold | none chosen — all business metrics are top-K by rank | n/a |
| Selected variant | A_C1.0, from pooled OOF | **identical in both runs** |

The selection is executed in code before `--stage all` reaches the TEST block, and `--stage oof`
exists precisely to prove the decision is reachable without TEST.

### B. Did the first TEST result influence any subsequent decision?

**Not causally — but the ordering cannot be disproven, and that is the honest finding.**

The trigger for the correction was the *feature-name column* of the §12 interpretability table, not
any TEST metric. The defect is verifiable against spec §2 without reference to any result. Nothing
downstream was altered: same variant, same C, same class weight, same calibrator, same π_target.

However, an auditor cannot verify a counterfactual. I saw run 1's TEST numbers before making the
fix. **And the fix moved TEST PR-AUC upward (0.03034 → 0.03706)** — the direction a test-fitter
would want. That coincidence is not evidence of misconduct, but it is exactly why the corrected TEST
figure must be discounted rather than treated as pristine.

### C. Was the correction independently justified by the specification?

**Yes, unambiguously.** Spec §2 names the reference levels: `individual_contributor`, `gmail`,
`en-IN` — "the most frequent level". `drop="first"` drops the alphabetically first level. The
baseline log even *printed* the intended references while the model used different ones, so the run
was internally inconsistent with its own output. Correction was mandatory regardless of results.

**Important technical note the baseline report gets right only after correction:** this is *not* a
free re-parameterisation. L2 shrinks coefficients toward zero, and zero means "equal to the
reference level", so changing the reference changes the fitted model. The two runs are different
models. That is why OOF moved too (0.01996 → 0.01943), which is itself evidence the change was not
TEST-directed: **a test-fitter would not have accepted a run that made OOF worse.**

### D. Can the corrected TEST result be treated as a valid final benchmark?

**No — but not primarily because of contamination.** The contamination risk is low and largely
mitigated. TEST fails as a benchmark for a more basic reason established in §7 below: **25 positives
cannot benchmark anything.** Its PR-AUC 95% CI is [0.01085, 0.13718] — an order of magnitude wide.

### E. How much confidence should be placed in it?

**Directional only.** Treat TEST as one weak corroborating observation that the model is not broken,
never as a performance figure to quote or a bar for future models to clear. Two independent reasons,
either sufficient on its own:

1. Opened twice, so it is no longer a virgin holdout in the strict sense.
2. Even as a virgin holdout, 25 positives has no discriminating power.

**Contamination status: LOW RISK, DOCUMENTED — but TEST is retired as a benchmark on power grounds.**

## 2. Calibration leakage audit

### The defect, confirmed

The baseline fits Platt scaling on pooled OOF predictions and then reports calibration metrics **on
those same predictions**. The Platt model consumes 2 degrees of freedom estimated from 100
positives, then is scored on the data that estimated it. The reported figures are optimistic.

### Quantified with a corrected nested procedure

Inside each outer fold's training window, the last 25% by time becomes a calibration block the model
never trained on. Platt is fitted there and applied to the outer validation block — strictly
out-of-sample at both stages, using only TRAIN.

| Fold | Model fit on | Platt fit on | Applied to |
|---|---|---|---|
| 1 | 2,481 rows (21 pos) | 827 rows (14 pos) | 2,239 val rows |
| 2 | 4,160 rows (49 pos) | 1,387 rows (30 pos) | 2,045 val rows |
| 3 | 5,694 rows (81 pos) | 1,898 rows (22 pos) | 1,903 val rows |
| 4 | 7,121 rows (97 pos) | 2,374 rows (20 pos) | 2,258 val rows |

| Metric | Current (in-sample) | Honest (nested) | Optimism |
|---|---|---|---|
| ECE | 0.001975 | **0.004573** | **2.3× understated** |
| Log loss | 0.063429 | 0.063801 | +0.000372 |
| Brier | 0.0116776 | 0.0116937 | +0.0000161 |
| Calibration slope | 0.9520 | **0.6913** | materially overstated |

### Reading

- **The optimism is real and concentrated in the calibration-specific metrics.** ECE more than
  doubles. Log loss and Brier barely move because at a 1.2% base rate they are dominated by the
  base rate itself and are insensitive to calibration quality — they should not be used to argue
  calibration is fine.
- **The slope finding matters most.** The report claims slope 0.95 (near-perfect). The honest slope
  is **0.69**, meaning the model is still meaningfully over-dispersed after calibration — it spreads
  probabilities about 45% further than the evidence supports.
- **Absolute magnitude remains small.** ECE 0.0046 against a 1.18% base rate is acceptable for
  decile-based operation. This is a reporting-honesty defect, not an unusable calibrator.

### Corrected procedure for future runs (TRAIN only, no TEST labels)

1. For each outer rolling fold, split the training window by time into model-fit (first 75%) and
   calibration-fit (last 25%).
2. Fit the model on the model-fit block; predict the calibration block.
3. Fit Platt on those calibration-block predictions and labels.
4. Apply to the outer validation block; pool across folds and report **those** figures.
5. For the deployed model: refit on all TRAIN, and fit the deployment calibrator on the most recent
   matured window inside TRAIN (fold 4's validation block) — never on data the final model trained on.

**Calibration leakage status: CONFIRMED, QUANTIFIED, NON-FATAL. Reported figures must be restated.**

### Finding 1 — Fold 4 ROC-AUC is 0.475, below chance

Fold 4 has the **second-highest PR-AUC (0.03598) and the highest PR lift (4.51×)**, yet its
ROC-AUC is **0.475 — worse than random**. These are not contradictory; they diagnose the problem.
PR-AUC is dominated by the very top of the ranking. With 18 positives, one or two landing near rank
1 inflates average precision while the ranking as a whole carries no information.

**Do not read fold 4's high PR-AUC as strength.** ROC-AUC is the prevalence-independent measure of
ranking quality, and on fold 4 it says the model orders leads no better than chance. Fold 4 is the
**most recent training fold and immediately adjacent to TEST**, which makes this the most
operationally relevant block in the entire experiment.

### Finding 2 — the signal is present in June and absent in July

|---|---|---|---|---|---|

| 4 | 07-15 → 07-24 | 3 / 226 | 1.80 | 0.2696 | none |

**The pooled OOF result is carried almost entirely by the two June folds.** In the twenty most
recent days of training data, the model's top decile produced 4 buyers where chance predicts 3.2.

This does not make the pooled result wrong — pooling is still the right primary estimator, and its
lift@10% CI [1.30, 2.90] genuinely excludes 1.0. But it substantially qualifies the baseline
report's claim that the signal is "consistent". **It is not consistent across time; it is
concentrated in June.**

### Is that instability, or just small folds?

Per the audit brief, a fold is not called unstable merely for a high or low number. Assessed properly:

- Folds 3 and 4 have 14 and 18 positives. Their top deciles contain 190 and 226 leads where chance

  significance. Their failure to show signal is *weak* evidence of absence.
- But ROC-AUC uses every pair, not just the top decile, and is far better powered. Folds 1–3 sit at
  0.645–0.683; **fold 4 at 0.475 is a genuine outlier**, and it cannot be explained away by fold size.
- Coefficient stability (§9) is excellent — the model is not thrashing. So this is not estimation
  instability; it is the *relationship between features and outcome* weakening in the most recent period.

**Temporal stability status: NOT ESTABLISHED. Signal is June-concentrated, and the most recent fold
ranks at chance.**

## 4. TEST vs OOF discrepancy

**Ratio: 0.03706 / 0.01943 = 1.907×.**

| Candidate explanation | Verdict | Evidence |
|---|---|---|
| Lower TEST prevalence | **Rejected — works the wrong way** | PR-AUC scales *with* prevalence. At TEST's 0.851% vs OOF's 1.184%, equal ranking ability predicts PR-AUC ≈ 0.0139, *below* OOF. Observed 0.0371 is 2.7× that. Prevalence makes the gap larger, not smaller. |
| Only 25 TEST positives | **Primary cause** | TEST PR-AUC 95% CI **[0.01085, 0.13718]** comfortably contains the OOF value 0.01943. The interval spans a factor of 12.6. |
| Sampling variance | **Primary cause** | Average precision with 25 positives is dominated by where the top few land. Fold 4 demonstrates the same mechanism inside TRAIN: PR-AUC 0.036 alongside ROC-AUC 0.475. |
| Temporal drift | **Contributes, in the unfavourable direction** | Signal weakened through July (§3). Drift predicts TEST should be *worse*, not better. |
| Model instability | **Rejected** | Fold coefficients are stable (§9): 14 of 14 mean SD ≈ 0.15, only 2 sign flips, both on near-zero coefficients. |
| Implementation error | **Rejected — decisive** | **ROC-AUC is prevalence-independent and agrees almost exactly: 0.60934 OOF vs 0.61539 TEST.** Ranking ability is identical across the two blocks. An ordering or split bug would move ROC-AUC too. |

**Conclusion: there is no discrepancy to explain.** The two blocks show the same ranking ability
(ROC-AUC within 0.006). PR-AUC differs because it is an unstable statistic at 25 positives. The
correct reading is that TEST *neither confirms nor contradicts* OOF — it lacks the resolution to do
either.

### What can legitimately be claimed

- **Over the pooled June–July window, ranking by model score beat random ordering.** The lift@10% CI
  [1.30, 2.90] excludes 1.0. This is a defensible claim.
- **Roughly a fifth to a quarter of buyers appear in the top decile**, versus one tenth by chance.
- **The model is not broken and shows no leakage.** ROC ≈ 0.61 on two independent blocks.

### What cannot be claimed

- **That the pilot will see 2.4× lift.** The TEST figure has CI [0.80, 4.40] — it includes *no
  benefit at all*. The point estimate is not a forecast.
- **That performance is stable.** The two most recent folds delivered 0.72× and 1.67×. A pilot
  starting today inherits the July regime, not the June one.
- **That 2.10× and 2.40× differ.** They are the same number inside noise.
- **Anything about individual lead probabilities.** Honest calibration slope is 0.69 (§2).

### Honest pilot expectation

Not 2.4×. The defensible planning range, weighting the recent folds appropriately, is
**1.2× – 2.0× lift@10%**, with a real possibility of no measurable benefit in any single fortnight.
Size the pilot to detect ~1.5×, not ~2.4×.

**Not production-ready. Pilot-worthy only as a queue-ordering aid with an explicit measurement plan.**

### Is the prior-shift strategy appropriate?

**Yes in design, and it should now be strengthened.**

- Correct in principle: it applies an intercept shift in log-odds, uses `π_target = 0.797%` taken
  from fold 4's validation block — the most recent matured window **inside TRAIN** — and never
  touches TEST labels. That is the right source.
- It demonstrably helped: on TEST it produced the best ECE (0.00348), log loss and Brier.
- **Strengthen it:** 0.797% came from a single 10-day block with 18 positives, so it is itself noisy.
  Estimate `π_target` from the trailing 28 days of matured labels rather than one fold, and refit it
  monthly. Ranking is stable under drift; absolute probability is not.
- **Never** estimate future prevalence from TEST or from any unmatured period.

**Drift status: CONFIRMED SIGNIFICANT. Strategy sound, input estimator should be widened.**

## 7. Sample size and statistical power

Power on the top decile, using the normal approximation to the count of hits:

| Block | Top-decile size | Expected hits (no skill) | SE | 2× lift = | Signal size |
|---|---|---|---|---|---|
| Pooled OOF | 844 | 9.99 | 3.14 | 19.99 hits | **3.18 σ** |
| TEST | 294 | 2.50 | 1.57 | 5.00 hits | **1.59 σ** |

Two models differing by 0.5× in lift@10% are separated by **1.59 σ on pooled OOF** and
**0.79 σ on TEST**.

### Statistically reliable conclusions

- The model beats random ordering over the pooled June–July window (lift@10% CI excludes 1.0;
  fold 1 p = 0.0018).
- Ranking ability is approximately ROC-AUC 0.61, consistent across two independent blocks.
- `f_seniority` and `f_email_class` carry signal; the four numeric features do not (§9).
- Monthly base-rate drift is real (p = 0.0067).

### Highly uncertain

- Any lift point estimate. Every business CI spans at least a factor of 2.
- Whether recent-period signal exists at all (folds 3–4).
- Whether any variant beats any other (§8).
- Absolute calibrated probabilities for individual leads.

### Is TEST large enough to compare two future models?

**No — decisively not.** At 0.79 σ, TEST cannot distinguish models differing by 0.5× in lift. It
would call two genuinely different models equivalent most of the time, and would occasionally rank
the worse one first.

### Should a single future holdout be used?

**No, not as the primary mechanism.** A single 2,939-row / 25-positive block is not a benchmark.

### Should rolling-origin evaluation become the primary comparison mechanism?

**Yes.** Pooled rolling-origin OOF has 4× the positives and twice the discriminating power, and it
additionally exposes temporal degradation — which is the single most important property of this
problem and is *invisible* to a single holdout. Retain a final holdout as a one-shot sanity check
only, and expand it by re-censoring as more labels mature. **No random splitting under any circumstances.**

## 10. Final decision

# B. BASELINE WITH METHODOLOGY FIXES REQUIRED

### Why not A (Robust baseline)

Three findings prevent it:

1. **Temporal stability is not established.** Signal is statistically present in the two June folds
   (p = 0.0018, p = 0.0344) and absent in the two July folds (p = 0.75, p = 0.27). The most recent
   fold ranks **below chance** (ROC-AUC 0.475).
2. **Reported calibration quality is optimistic.** Honest nested calibration gives ECE 0.0046, not
   0.0020, and slope 0.69, not 0.95.
3. **Model selection is a statistical tie**, not a win — every paired-bootstrap CI contains zero.

### Why not C (Baseline invalid)

Nothing is wrong with the dataset, the leakage controls, or the execution:

- Reproduction is exact to five decimals.
- Zero blocked fields reach the matrix; zero temporal violations; the `f_`/`a_` guard is asserted in code.
- No stop condition triggered.
- Coefficients are stable and directionally consistent with the V3 univariate analysis.
- Pooled OOF lift@10% CI [1.30, 2.90] genuinely excludes 1.0.
- TEST contamination risk is low, documented, and the fix was independently mandated by the spec.

The methodology defects are in **reporting and calibration evaluation**, not in construction.

### 1. What must be fixed before the next experiment

| # | Fix | Severity |
|---|---|---|
| 1 | Replace in-sample Platt evaluation with the **nested calibration** procedure in §2. Restate ECE (0.0046) and slope (0.69). | **Required** |
| 2 | Make **pooled rolling-origin OOF the primary comparison mechanism**. Retire the single holdout as a benchmark. | **Required** |
| 3 | Report **per-fold ROC-AUC alongside PR-AUC** always. Fold 4's below-chance ranking was invisible in the baseline report because only PR-AUC was tabled per fold. | **Required** |
| 4 | Restate the selection as a **tie broken on calibration and stability**, not a PR-AUC win. | **Required** |
| 5 | Widen `π_target` to a trailing 28-day matured window instead of one 18-positive fold. | Recommended |
| 6 | Add a **temporal-degradation check** to the standard report: binomial test on top-decile hits per fold. | Recommended |
| 7 | Investigate `f_locale`'s PR-AUC/ROC-AUC conflict. | Recommended |

### 2. What can remain unchanged

- `final_trainset_v3.sql` — validated four times, no defect found.
- The 7-feature definitions and the target definition.
- The 80/20 boundary and the four fold boundaries.
- Logistic Regression A, C = 1.0, `class_weight=None`.
- Preprocessing (one-hot with most-frequent references, scaler inside the pipeline).
- The prior-shift *approach* (only its input estimator widens).
- The `f_`/`a_` prefix guard.

### 3. Can the corrected TEST result be retained as an internal reference?

**Yes — as a labelled internal reference only.** Record it as
*"TEST (2,939 / 25 pos, opened twice): PR-AUC 0.0371 [0.0109, 0.1372], ROC-AUC 0.6154, lift@10%
2.40× [0.80, 4.40]"* — always with the CI and the disclosure. Never as a target for future models to
beat, and never quoted externally without them.

### 4. Is a fresh holdout required?

**Yes, eventually — but not by re-splitting V3.** Re-splitting the same 14,692 rows creates no new
information. The correct action is to **wait for labels to mature and re-censor forward**: leads from
2026-08-10 onward become available as their 21-day windows close. That yields a genuinely untouched
holdout with new positives. Until then, rolling-origin OOF is the benchmark.

### 5. Does calibration need to be redesigned?

**The evaluation does; the calibrator does not.** Platt on log-odds is the right choice at 100
positives. What must change is that it is currently *scored on its own training data*. Adopt the
nested procedure and restate the numbers.

### 6. Should the current baseline be frozen as the benchmark?

**Yes — with the pooled OOF figures as the benchmark, not TEST.** Freeze:

> **Benchmark V1** — LogisticRegression(C=1.0, class_weight=None), 7 V3 features.
> Pooled OOF (8,445 rows, 100 positives): **PR-AUC 0.01943**, ROC-AUC **0.60934**,
> lift@10% **2.10× [1.30, 2.90]**, honest ECE **0.0046**, honest calibration slope **0.69**.
> Known limitation: signal concentrated in June; fold 4 ROC-AUC 0.475.

Any future model must beat **that**, on the same four folds, by more than the fold-to-fold spread.

## 11. Next experiment recommendation

# A. Controlled feature enrichment using additional SAFE point-in-time features

**Exactly one experiment. Not executed.**

### Why A, given only 160 positives

**The audit shows the feature set — not the estimator — is the binding constraint.** Four of the
seven approved features (`f_company_len`, `f_company_is_placeholder`, `f_hour_sin`, `f_hour_cos`)
contribute nothing measurable to pooled OOF PR-AUC. The model's entire signal rests on
`f_seniority` and `f_email_class`, with `f_locale` conflicted. A model carrying two effective
features and reaching ROC-AUC 0.61 has not exhausted the estimator; it has exhausted the inputs.

### Why not B (tree-based comparison)

Two independent reasons, either sufficient:

1. **No power to detect an improvement.** §7 shows pooled OOF separates models differing by 0.5×
   lift at only 1.59 σ. A tree model would have to be dramatically better to be *detectably* better,
   and §8 already shows four Logistic Regression variants are statistically indistinguishable from
   one another — the evaluation cannot resolve the differences that exist.
2. **Nothing for trees to find.** Trees earn their keep on interactions and non-linearities. With 14
   design columns, four of them inert, and 100 pooled OOF positives, a boosted model will fit the
   June-specific signal that §3 shows does not persist into July. It would very likely look better
   in CV and worse in reality.

### Why not C (another Logistic Regression experiment)

The LR configuration space is exhausted. All four variants tie inside bootstrap noise, and the
`C ∈ {0.1, 1.0}` sensitivity moved PR-AUC by 0.001. Re-running the same estimator on the same
features cannot answer any open question.

### What the enrichment experiment must include

Scope it tightly — 100 pooled OOF positives supports perhaps 3–5 additional columns, not a wave.

1. **`a_jobtitle_raw` text features.** 6,756 distinct titles currently collapsed into 5 buckets, and
   `f_seniority` is already the strongest contributor. Extract 3–5 binary indicators for high-signal
   tokens (`director`, `founder`, `head`, `student`) or a small hashed representation. Highest
   expected value in the set.
2. **`a_company_raw` firmographic enrichment.** 12,246 distinct employers currently reduced to a
   length and a placeholder flag. Company size and industry band are the classic B2B predictors and
   are entirely absent today.
3. **Both must pass the V3 admissibility rules** — point-in-time from the form payload, written
   within t₀ + 1 hour, not backdated. Any new column joins the `f_` namespace and the guard assertion.
4. **Resolve `f_locale`** in the same experiment, since enrichment may explain its PR/ROC conflict.

### The experiment must also answer the temporal question

Evaluate **per fold with ROC-AUC and the binomial top-decile test**, not only pooled. The central
question is not merely "is PR-AUC higher" but **"does enrichment restore signal in the July folds?"**
If richer features still fail on folds 3 and 4, the conclusion is that the pre-purchase signal
genuinely decayed — and the answer is instrumentation (`tracking_events` remains at 0 rows), not
modelling.
