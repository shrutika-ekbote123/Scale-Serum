# NOTICE - third-party components

Generated by `scripts/bakeoff/provenance.py` on 2026-09-09. Regenerate when a component changes.

Covers the components **Vision Lab introduced**. The wider service's existing dependencies (FastAPI, motor, google-genai and so on) are not repeated here.

## Why this file exists even though we do not distribute a binary

Vision Lab runs server-side, and permissive licences attach most of their
obligations to *distribution*. Running software to provide a service is
usually not distribution - so today this file is mostly a record.

It stops being a record the moment any of these happen:

- Vision Lab is shipped on-premise to a customer
- a model or binary is bundled into an image handed to someone else
- inference moves into the browser

Reconstructing provenance after the fact is the expensive version of this.

## Runtime components

### FFmpeg

- **Used for:** Decoding the creative, sampling frames, detecting shot changes, extracting audio
- **Licence:** LGPL-2.1+ or GPL-2+/GPL-3+ DEPENDING ON THE BUILD
- **How we use it:** invoked as a separate process via subprocess

The Windows build used in development (gyan.dev full_build) reports --enable-gpl --enable-version3, so it is a GPL-3 build. Debian and Ubuntu's packaged ffmpeg is also typically GPL.

This matters far less than it looks, because of HOW we use it: vision_lab/media.py shells out to the ffmpeg BINARY and reads its output. We do not link against libavcodec, and the GPL's copyleft reaches linked code, not separate programs exchanging data.

Two rules keep it that way:
  1. Install ffmpeg as a system package on the server (apt install ffmpeg). Never vendor the binary into this repo or into an image we distribute.
  2. Never switch to a Python binding that LINKS ffmpeg libraries (PyAV, ffmpeg-python's native bindings) without a licence review - that changes the analysis completely.

If ffmpeg ever has to ship WITH the product, use an LGPL build (no --enable-gpl) and comply with LGPL relinking terms.

### OpenCV (opencv-python-headless)

- **Used for:** Frame resizing, template matching, colour maps, image encoding
- **Licence:** Apache-2.0 (OpenCV 4.5+)
- **How we use it:** imported as a Python library

Permissive. Preserve the notice if we ever distribute a bundle.

### Tesseract OCR

- **Used for:** Reading on-screen text, word counts, CTA and price detection
- **Licence:** Apache-2.0
- **How we use it:** invoked as a separate binary through pytesseract

Permissive. The binary is installed on the box, not vendored.

### ONNX Runtime

- **Used for:** Running the saliency model on CPU
- **Licence:** MIT
- **How we use it:** imported as a Python library

Optional - absent, saliency falls back to the classical baseline.

### Pillow, NumPy, boto3, httpx

- **Used for:** Image encoding, arrays, S3, HTTP
- **Licence:** MIT-BSD family / Apache-2.0
- **How we use it:** imported as Python libraries

Permissive; already in the wider service's dependency set.

## Saliency model

- **Model:** UNISAL
- **Code licence:** Apache-2.0 (repository; weights committed within it)
- **Weights licence:** Apache-2.0 (repository; weights committed within it)
- **Trained on:** SALICON, DHF1K, Hollywood-2, UCF-Sports
- **SHA-256:** recorded in `vision_lab/vision_framework.json` and verified by the worker at boot

### Attribution required by Apache-2.0

UNISAL is distributed under Apache-2.0, which requires the copyright notice and
licence text to be preserved in any distribution. Its README also asks that use
be cited:

> Droste, R., Chen, J., Noble, J.A. — *Unified Image and Video Saliency
> Modelling*, ECCV 2020. https://github.com/rdroste/unisal

The full licence text ships with the exported model's provenance record in
`vision_lab/vision_framework.json` and in `vision_lab/BAKEOFF_LICENCES.md`.

### The open question on these weights

The weights are committed **inside** the Apache-2.0 repository, which is a
reasonable basis for relying on that licence - a stronger position than a
checkpoint hosted outside anything the LICENSE covers.

What Apache-2.0 cannot settle is the training data. UNISAL was trained partly on
**Hollywood-2** (clips from commercial feature films) and **UCF-Sports**
(broadcast footage). Whether trained weights are a derivative work of their
training data is unsettled and varies by jurisdiction, and it is not something
the model's author could license away.

This is recorded rather than resolved. Vision Lab ships with `VL_ENABLED=false`
by default, so the decision to expose these scores to customers stays an
explicit act. If the answer comes back badly, MSI-Net (MIT, declared on the
weights, SALICON-only) is already adapted and is a one-line config change - at
the cost of measurably worse brand-mark detection.

## Evaluation datasets - never shipped

MIT1003 and CAT2000 are downloaded to `scripts/bakeoff/workspace/` to
benchmark candidate models. They are **evaluation inputs, not product
components**: gitignored, never deployed, never redistributed, and absent
from every artefact that reaches a customer.
